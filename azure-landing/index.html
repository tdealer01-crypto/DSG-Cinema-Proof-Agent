Current system only

The verification path is deliberately small.

The public product surface now explains only the current runtime: bounded request, deterministic policy, exact verification, evidence/replay, and proof. No legacy orchestration layer is required to understand or use DSG Verified Execution.

01Agent / App

Marketplace, CI, SDK, or application proposes an observed action.

02Verification Intake

Bind execution, trace, approved plan, proposed action, and explicit safety facts.

03Plan Alignment

Authorization, scope alignment, and constraints derive ALLOW / REVIEW / BLOCK.

04Exact Z3

Cinema builds the bounded decision problem and requires exact global-optimum verification.

05Evidence + Replay

Record execution result, replay match, evidence completeness, and hash bindings.

06Proof Receipt

Portable receipt exposes exact verification, decision, proof hashes, and cost/run.

Proof Receipt

Evidence that can survive the demo.

The useful output is not a dashboard animation. It is a machine-readable receipt that records why the decision exists and what exact verifier confirmed it.

Plan-boundApproved plan and proposed action are represented by canonical SHA-256 hashes.
ExactA receipt requires verified=true and VERIFIED_GLOBAL_OPTIMUM from the exact Z3 path.
ReplayableRequest hash, proof hash, context hash, and replay result remain inspectable.
MeterableEvidence completeness and cost/run sit beside the verification result.
